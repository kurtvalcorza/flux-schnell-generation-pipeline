## Three things this tutorial does that most of the fleet's others do not

**It loads a 12 B transformer 4-bit because nothing else fits.** The three bfloat16 shards are 23.8 GB; Section 6 quantises them to NF4 with double quantisation as they load (about 6.6 GB) and trains the LoRA over that base (QLoRA). Every number the notebook prints is the 4-bit model's, and the adapter manifest records `nf4`.

**It keeps the text encoders and the transformer off the GPU at the same time.** CLIP-L and T5-XXL are 9.7 GB in float16, so Section 5 encodes the six captions and the new prompt, keeps the embeddings, and releases both encoders before Section 6 loads the transformer; `encode_prompts` refuses to run while the transformer is resident. Two 4-bit transformers do not fit either, so Section 9 releases the adapted one before the fresh pipeline reloads the artifact and adopts the same embeddings.

**It scores a generator without pretending a number is quality.** Generation has no ground truth, so the notebook reads three kinds of number and names each: the held-out *flow-matching loss* (the training objective on photographs the model never trained on, with identical noise for the frozen and the adapted model; the only assertion is the guaranteed one, that the kept epoch's validation loss is no higher than the frozen model's, and the test loss is printed, not asserted), CLIP scores of generated images (prompt alignment, which species CLIP thinks it sees, closeness to the held-out photographs), and the same CLIP scores on the real photographs — the *real-photo ceiling*. None of them is a human judgement.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules (`pipeline.py`, `samples.py`, `metrics.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrite makes the weights root working-directory-relative and removes internal relative package imports), Section 3 carries the two snapshot manifests inline and asserts each against the module's constants before staging, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifests, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files` fetches only the manifest entries that are absent, from the ungated mirror `unsloth/FLUX.1-schnell` at its immutable revision (never `main`, never the gated upstream), and `stage_missing_scorer_files` does the same for the scorer; `verify_snapshot` checks that the manifest names the pinned staging source and re-hashes every entry, `verify_scorer_snapshot` re-hashes the scorer's; `FluxSchnellPipeline.from_pretrained(weights_dir=WEIGHTS_DIR, use_lora=True)` loads the VAE, both tokenizers and the scheduler config; the text encoders are loaded by `encode_prompts` and released by `release_text_encoder`; the transformer is loaded 4-bit by `load_transformer` with an untrained LoRA attached. Every file is safetensors or JSON/text; nothing is unpickled and no remote code runs.
- **Stages (§4.1):** `fetch_sample_dataset` / `load_byod_dataset` (sample acquisition) → `dataset_manifest` + `validate_dataset` refusal probes (validation, with the ceilings and a dataset digest) → seeded stratified roles (36 / 12 / 12) → `pipe.encode_prompts` + `export_prompt_cache` + `release_text_encoder` → `pipe.load_transformer` → `pipe.evaluate` and `pipe.generate` + `score_generations` on the frozen model with `real_photo_baseline` (baseline) → `pipe.adapt` (bounded QLoRA fine-tuning) → `pipe.evaluate` / `pipe.generate` again on identical inputs (evaluation) → `pipe.generate` on a new prompt (inference) → `pipe.save_artifact` → `pipe.release_transformer` → `FluxSchnellPipeline.from_artifact(..., prompt_cache=cache)` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** CLIP cosine similarities and the argmax label rule are labelled as what they are; the flow-matching loss is the training objective, not a quality measure; no threshold is set and no calibration is claimed; every number is labelled as the 4-bit model's.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the frozen model is scored before adaptation on the same seeded latents, noise and noise levels, and the real-photo ceiling is scored on the same photographs; every metric is labelled sample-sanity evidence from 12 held-out photographs and 6 generated images with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** the split is seeded and stratified per species, no image appears in two splits (`check_split_disjoint`), validation selects the epoch and the test records are used for nothing but the final comparison; the notebook states that the captions are one template per species and that photographs of the same individual or observer should be grouped in real data. In BYOD mode the split is by caption.
- **Ceilings (VAL6):** the image-size range, the caption length, the token truncation and the record range are stated in the Prerequisites and printed from the schema before the model runs; three refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user records flow through the same validation, encoding (the transformer is released first if resident), baseline, adaptation, evaluation, generation, export and reload cells. The expected zip layout, the image and caption contract and the privacy guidance — photographs of identifiable people and licensed material are restricted data — are stated in the Prerequisites and in Section 4, and a captions CSV is written to `outputs/` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
